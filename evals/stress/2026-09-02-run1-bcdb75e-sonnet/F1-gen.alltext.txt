# Stage 05b — MULTI-CURRENCY — SPEC

Slice: `multi-currency`, extending the accepted `ledger-core` slice (`ledger/__init__.py`, credit/debit/capture/refund).

## Context
`Ledger` today holds one global integer `balance` and a flat `captures` dict keyed only by capture id. This slice makes currency a first-class dimension: every balance-affecting call is scoped to a currency code (e.g. `"USD"`, `"EUR"`), and a currency's balance/captures must be completely isolated from every other currency's.

## FRs
- **FR-1** Ledger holds a balance per currency code, defaulting to 0 for any currency not yet touched (no pre-registration required).
- **FR-2** `credit(currency, amount)` adds `amount` to that currency's balance only.
- **FR-3** `debit(currency, amount)` raises `InsufficientFunds` if `amount` exceeds *that currency's* balance. Other currencies' balances are irrelevant — no pooling, no implicit FX.
- **FR-4** `capture(currency, capture_id, amount)` debits `currency` and records the captured amount scoped to `(currency, capture_id)`.
- **FR-5** `refund(currency, capture_id, amount)` raises `RefundExceedsCapture` if `amount` exceeds the recorded capture for that `(currency, capture_id)` pair; on success, credits `amount` back to `currency`'s balance and reduces the recorded capture.
- **FR-6** The same `capture_id` string used under two different currencies is two independent records (e.g. `capture("USD","c1",10)` and `capture("EUR","c1",5)` don't interfere).

## Domain laws touched (re-scoped, not new)
- **D1** balance MUST NOT go negative — now evaluated **per currency**. A healthy USD balance must not mask a negative EUR balance, or vice versa.
- **D3** refund MUST NOT exceed capture — now evaluated **per `(currency, capture_id)`**.

## Out of scope this slice
- Currency conversion / FX between currencies — each currency is an isolated ledger, by design
- Currency code validation (ISO-4217 allow-list, case normalization) — any hashable string is accepted
- Persistence backend, multi-tenant isolation — unrelated concerns, unchanged from ledger-core

## Breaking-change decision needed (see Ask of you)
Current signatures (`credit(amount)`, `debit(amount)`, `capture(cid, amount)`, `refund(cid, amount)`) have no currency arg. Two options:
- **(a)** currency becomes a required leading positional arg on all four methods — explicit, breaks the 3 existing call sites in `tests/ac/test_ledger.py`, `tests/inv/test_D1_balance.py`, `tests/inv/test_D3_refund.py`.
- **(b)** currency is an optional kwarg defaulting to `"USD"` — old call sites keep working untouched, multi-currency is opt-in.

**Recommendation: (a).** A silently-defaulted currency risks a caller forgetting to pass one and corrupting the wrong ledger, which is exactly the bug class D1 exists to catch.

## Acceptance criteria for execute
- **AC-1** existing single-currency credit/debit test still passes, updated to pass currency explicitly.
- **AC-2** (new) crediting USD then debiting EUR beyond EUR's (zero) balance raises `InsufficientFunds`, even though USD has funds — proves no cross-currency pooling.
- **AC-3** (new) capture/refund round-trips correctly and independently for two currencies sharing the same `capture_id`.
- **D1** (rewritten) per-currency negative-balance rejection; red twin `INV_MUTANT=D1` must still make it fail.
- **D3** (rewritten) per-currency refund-exceeds-capture rejection; red twin `INV_MUTANT=D3` must still make it fail.
