# Stage 05b — journal-transfers — SPEC

(committed to `docs/cascade/05b-journal-transfers.md`, `ade711b`)

Slice: journal-transfers, FR-4. Extends the existing `Ledger.transfer(other, amount, currency)` (already exercised by D4) with an optional `idempotency_key` and a per-account `journal` — one debit entry on `src`, one credit entry on `dst`, per applied transfer. See the committed file for full Stories/ACs (AC-1…AC-6), files touched, and required tests.

Key design points baked into the spec:
- `transfer(self, other, amount, currency=DEFAULT_CURRENCY, idempotency_key=None)` — extends the existing method rather than adding a parallel API.
- No key ⇒ no dedup (today's behavior, keeps `test_D4_conservation.py` and existing multi-currency AC tests green unmodified).
- Same key + same payload ⇒ no-op replay (apply once).
- Same key + different payload ⇒ raise `IdempotencyConflict` (fail closed, not silently ignored or merged).
- Failed debit ⇒ no journal entries on either side (atomic, for free, since `debit()` already raises before any mutation).
- Proposes a new **D5** law ("replay applies at most once") with validator/red-twin commands, following the `INV_MUTANT` pattern — left UNPROVEN/not in the envelope since D# lines are human-owned.
